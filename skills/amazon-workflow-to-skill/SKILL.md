# 把亚马逊工作流程整理成技能

先从当前任务和用户提供的资料中提炼实际做过的步骤、工具、口径、纠错以及输入输出；缺少会改变流程的信息时，只补问关键缺口。

## 确定沉淀范围

识别下次还能使用的处理方法，分开记录已验证步骤与待验证设想。若只有单个 ASIN 的结论或一次性数据，先整理任务记录，说明还缺哪些可复用的操作依据。

若可以访问目标技能仓库，先查看已有技能和贡献规则。适用场景与输入输出一致时更新已有技能；确实是独立任务时再新增。目的地不明确时输出可交付的技能文件夹，不擅自修改其他项目或个人全局设置。

## 提炼关键内容

- **触发场景**：什么请求应使用技能，容易混淆的相邻请求有哪些。
- **输入资料**：需要哪些报表、字段、站点、时间范围、币种、单位和数据来源；哪些是必需项。
- **处理方法**：保留影响正确性的步骤、字段关系、判断分支、实际纠错和停止条件；删除泛泛建议。
- **业务判断**：销量区间、第三方估算和实测值分别记录。商品阶段、利润约束、ACOS 目标等阈值由实际依据或输入参数决定，不根据一个案例虚构通用标准。
- **缺失信息**：未知值保留未知，不将缺失值替换成零。核心输入不足时，输出缺失项与可完成的部分；不要编造完整结论。
- **输出要求**：说明需要交付的表格、文案、文件或行动项，以及如何检查这些结果。

只保留复现流程需要的工具能力和数据口径，不复制账号凭证、真实经营报表或无关客户资料。依赖外部工具时说明需要的能力；工具不可用时如实说明影响，不声称已完成真实取数或业务验证。

## 编写技能

使用独立文件夹 `skills/<name>/`，名称采用小写英文、数字与短横线，且不超过 64 个字符。入口为 `SKILL.md`：

```yaml
---
name: amazon-search-term-review
description: 根据指定店铺、站点和周期的搜索词报表整理复核清单，适用于用户要求复核搜索词表现或准备人工优化事项。
---
```

上面仅演示文件头格式，不代表已有对应业务技能。正文根据本次真实流程写入所需输入、处理方法、缺失项处理和输出要求。只有具体任务需要时才增加 `scripts/`、`references/`、`assets/`；资源必须随技能一起交付，避免依赖作者电脑上的绝对路径。

不把本次用户的临时偏好扩展为团队永久要求。技能创建和安装不自动授权写入亚马逊后台、发布广告或上传数据；按照用户已授权的任务范围处理实际操作。

## 验证并交付

1. 检查名称、描述和文件夹是否一致，所需参考资料是否齐全。若目标仓库提供验证工具，运行其规定的结构检查。
2. 用一个脱敏的正常案例试用；流程涉及核心输入缺失时，再检查缺失输入是否产生明确的补充要求，而不是捏造结果。
3. 新增脚本应实际运行并检查关键输出。结构检查、合成案例试用和真实业务试用分别说明，不互相替代；无法验证的部分列明原因。
4. 给出技能文件夹、调用示例、来源流程与验证范围。若在团队仓库内新增技能，同时更新该仓库的技能目录。依照用户已授权的范围提交；没有发布授权时交付本地结果。

调用示例：`$amazon-workflow-to-skill 把这次已经跑通的搜索词报表核对流程整理成团队技能，保留字段口径和缺失报表的处理规则。`
